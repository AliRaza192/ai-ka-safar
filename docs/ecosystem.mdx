## Kaise juda hai: ek source, teen gateways

Diagram upar se neeche padha jaata hai: system kaun use karta hai, kya connect karta hai, woh connections kis cheez se bane hain, aur sach kahan rehta hai. Chaar layers, ek flow.

### Layer 1 — Teen audiences, teen darwaze

- **Learners** apne free Claude par aate hain. Ek connector add karo, ek baar authorize karo, aur seekhna shuru karo. Kuch install nahi, kuch pay nahi karna.
- **Builders** apne coding agent ke andar aate hain — Claude Code ya OpenCode. Unka darwaza ek plugin hai, kyunki construction work wahi hota hai.
- **Authors** woh agents hain jo derivative books produce karte hain, topic, age, aur profession ke hisaab se rewrite hoti hain. Unka darwaza ek publishing pipeline hai.

Har audience se wahi milo jahan woh already kaam karta hai. Koi naya app adopt nahi, koi naya habit nahi.

---

### Layer 2 — Patle gateways, har audience ke liye ek

- **Zia Tutor AI gateway** teaching lane: learner ka Claude kis se baat karta hai jab Zia greet karta hai, samajh check karta hai, aur progress record karta hai.
- **Zia Developer AI gateway** construction lane: coding agent kis se baat karta hai jab Zia architecture chunta hai, spec likhta hai, aur build karta hai.
- **Publishing gateway** derivative-book pipeline, author agents ko canonical material deta hai jo woh specialize aur rewrite karte hain.

Gateways jaan bujhkar patle hain: yeh decide karte hain unki audience kya dekh sake aur usse shape dete hain. Saari asli functionality ek layer neeche rehti hai.

---

### Layer 3 — Component MCP packages, har gateway par mounted

- **content** — kitab as System of Record. Har lane verified chapters, definitions, aur patterns padhta hai, training data se guess karne ki jagah.
- **learning** — learner state. Progress, history, jahan chhoda. Yeh woh hai jo Zia Tutor AI ko din baad conversation resume karne deta hai.
- **pedagogy** — teaching moves. Kaise samjhana hai, kab quiz lena hai, kaise correct karna hai — tools mein encode, model ki improvisation par chhoda nahi.
- **builder** — build patterns. Specs, `SKILL.md` templates, aur recipes jo Zia Developer AI working agents mein assemble karta hai.

Composition hai, duplication nahi. Har gateway sirf woh mount karta hai jo use chahiye, toh content package ek baar fix karo aur teeno lanes ko fix mil jaata hai.

---

### Layer 4 — Ek source of truth, ek database

- **Git repo (canonical)** — kitab as MDX. Har chapter, figure, aur definition ka master copy. Yahan se book change karo, upar sab inherit karega.
- **One Postgres** — baaki sab: relational data, vector embeddings, aur full-text search ek hi database mein. Canonical MDX isme ingest hota hai taake packages query fast karein.

Kitab ki apni thesis apne upar apply: default par consolidate, jaan bujhkar specialize.

---

### Yeh shape kyun?

Sach ek baar define hota hai (Git), ek baar store hota hai (Postgres), reusable capabilities (packages) ke through expose hota hai, aur patle, audience-shaped darwazon (gateways) ke through deliver hota hai. Baad mein naya product add karna (naya audience, naya lane) — bas ek aur patla gateway usi packages par. Source kabhi nahi badalta. Isliye yeh ecosystem hai, teen alag apps nahi.

## Business model — Ek base, paanch layers: foundation se upar har layer kamaata hai

Tumne jo ecosystem abhi dekha woh ek repeatable pattern ka instance hai: **FDE AF Model**. Wohi base vertical, AI-native businesses mein badalta hai, aur foundation se upar har layer woh jagah hai jahan hamare graduates build karte hain aur kamaate hain.

| Layer | Naam | Status |
|-------|------|--------|
| 0 | **Foundation framework** | BASE — MCP, Markdown, pgvector, Better Auth. Ek baar built; sab kuch isi par khara hai |
| 1 | **Content System of Record** | EARNS — Reusable SoR components banao aur license karo, solo ya ecosystem contributions ke saath |
| 2 | **Teaching & development ecosystem** | EARNS — Scale par education, near-zero inference cost, kyunki user model laata hai |
| 3 | **Vertical ecosystems** | EARNS — Domain partnerships: expert twin aur rights-cleared material license karo |
| 4 | **Customer instances** | EARNS — FDE engagements: ek company mein deploy karo, phir recurring revenue ke liye chalao |

![FDE AF earning map: paanch-layer stack foundation framework se lekar content System of Record, teaching aur development ecosystem, vertical ecosystems, aur customer instances tak, jahan graduates har foundation se upar layer par kama sakte hain.](/img/ecosystem/fde-af-earning-map.png)
